# Sports Zenith — secure automatic Survivor entry connection after email sign-in
Date: October 10, 2026 ET. Existing production Sports Zenith; critical owner-review UX fix.

## Requested behavior and root cause
Owner rightly objected to needing to remember and manually type a Survivor entry name or separate one-time pool claim code **after successfully signing in with the existing passwordless email code**. Prior design assumed every logged-in member was a first-time claimant. The pool entry was safely in private server data but lacked the durable auth-account-to-entry relationship; the local claim hash alone was never a recoverable readable claim code.

## Actual new live behavior
- An **operator-provisioned** association of the designated sign-in email to the existing private pool entry was saved outside Git and outside the public website at `/home/ubuntu/sports-zenith-private/survivor_owner_entitlements.json`. It contains only a normalized-email SHA256 fingerprint and an exact entry reference (NOT an email address, user token or a raw one-time claim code). Owner entitlement file is 0600, directory 0700. This is NOT a general method for arbitrary users to claim a pool entry.
- `survivor_verified_owner_autolink.js` requires the provider-authenticated user ID **and** `user.emailVerified===true` from InsForge. The client cannot supply either owner email or entry name for this automatic path. The server compares the email fingerprint exclusively against the protected operator manifest, checks the exact existing private pool entry, refuses conflicting ownership and uses InsForge admin database original `survivor_claims` compare-and-swap to atomically reserve it for this identity. Admin `survivor_entries` is inserted and read back by owner ID; only *after success* is local fallback linkage updated. Claims pre-owned by another identity or a duplicate/inactive existing record fail closed. Repeated login reads the existing owner without duplicate writes. No one-time code is typed or recovered, and no original private used-team/pick state is mutated.
- Both `GET /api/survivor/state` and `GET /api/account/summary` trigger the same authenticated automatic entitlement check before returning private data, with in-process single-owner concurrency handling. Other accounts remain unauthorized; anonymous account and Survivor endpoints continue returning HTTP 401. A manual claim route is still available for operator-provisioned additional entries but now refuses attempts to steal an entry reserved for another verified sign-in.
- The owner's Survivor UI now auto-loads linked entries and shows the historical used teams/scores via the existing private API. The obsolete prominent name/code form is replaced by **Refresh my entries** if no assignment was found, and the manual-entry claim form is a collapsed, explicitly optional manager flow. During authentication, private data is LOADING rather than falsely displaying an unlinked-error form. The original pick editor, pool deadline enforcement and external submission caveat were not changed.
