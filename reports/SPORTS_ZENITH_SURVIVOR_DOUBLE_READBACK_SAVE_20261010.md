## Verified vulnerability
- Original `src/SurvivorPickEditor.jsx` said "Saved in Sports Zenith" immediately after ANY HTTP 2xx response from POST `/api/survivor/save-picks`, without validating the returned JSON status, opening the private original member file again, or independently querying the user's saved private record. Selecting **Add** could look like a save because there was no clear unsaved-draft indicator.
- The backend Python bridge `commercial_web/survivor_pick_bridge.py` already checks cutoff, ownership upstream, private write and original rule restrictions; we did not weaken it. Its existing operator-prepared uncommitted changes in `commercial_web/survivor_pick_bridge.py`, `premium_ui/survivor_editor.py` and `tests/test_survivor_private_picks.py` remain untouched/uncommitted in this patch.

## Layered readback fix
- New server-only pure `commercial_web/survivor_save_persistence_proof.js` checks the private ORIGINAL disk source after successful Python bridge execution: exact authenticated owner's entry key, current pool week, current member week, exact ordered selected teams, `week_N.picks` rows, real `manual_saved_at` within two minutes, manual-saved source, pending/unresolved grade, member alive, original `submitted=false`, and bridge status/owner/teams agree. It checks the `current_pick_status`, distinguishing fully saved `SAVED_NOT_SUBMITTED` from an explicitly incomplete Week 6 `INCOMPLETE_SAVED` one-of-two selection; both are *only* saved Zenith drafts, NOT external submissions. No source or user record written by verification.
- POST `/api/survivor/save-picks` now returns HTTP 200 with `status=PERSISTED_IN_ZENITH_NOT_EXTERNAL_POOL`, `verified_disk_readback=true`, original real save timestamp and original `pick_status` **only after the second private file read** confirms the exact saved ticket. Failure returns HTTP 503 `PERSISTENCE_NOT_VERIFIED` and an honest suggestion to refresh; it does not pretend definitely saved or unsaved because a partial write may have occurred. An empty-team POST is refused before the Python writer to avoid silent clearing under an unverified response. The existing authenticated owner check and no-external-submission rules remain.
- New browser-safe `survivor_save_client_verification.js` independently checks a fresh authenticated `GET /api/survivor/state?entry=...` after the POST. Only if the returned linked active owner entry, pool week, exact selected teams, original saved-status and required pick count also agree may the editor say **"Saved and verified in Sports Zenith. Your external pool has NOT been submitted."** A 200 from an outdated service or a stale/incorrect private readback MUST display an error instead and disable repeat saves until the member refreshes. For incomplete multi-team Week 6, success copy says **"Partial draft saved and verified"** with original required count rather than claiming a complete pool entry.
- The editor now shows an unambiguous **DRAFT ONLY** warning immediately after Add, and cannot save empty or unauthorized selections. A failed verification keeps the draft visible and does not call onSaved, fabricate a confirmation, submit to the organizer, or alter the original pool ledger.
- `public-brand-consistency.test.js` now expects the stricter "Saved and verified in Sports Zenith" language, not the old unsafe generic message.
