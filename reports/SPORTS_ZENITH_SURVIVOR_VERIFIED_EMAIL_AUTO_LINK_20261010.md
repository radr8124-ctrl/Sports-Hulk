## Implementation
- Server-private original preassignment manifest: `/home/ubuntu/sports-zenith-private/survivor_owner_entitlements.json`, directory mode 0700, file mode 0600, outside the Git repository and public web root. Stores only a SHA256 normalized-email fingerprint and the privately preassigned entry name; no raw email, password, OTP or claim code. The manifest is validated before use and can be updated for other verified owner accounts by the operator only.
- New pure, testable `commercial_web/survivor_verified_owner_autolink.js`. **Requires authenticated InsForge provider user with `emailVerified===true`, immutable provider user ID and email whose normalized fingerprint matches the private operator entitlement.** User-supplied names, localStorage values, email fields, claim-code strings, query parameters, unauthenticated clients and arbitrary team names can never activate this binding.
- `GET /api/account/summary` and `GET /api/survivor/state` now perform a server-side, account-verified ONE-TIME auto-provision before fetching private records. It checks original pool entry exists; refuses owner conflicts in local registry and authoritative InsForge DB; checks original `survivor_claims` is unclaimed or owned by the same verified user; atomically claims it (conditional compare-and-swap), inserts the exact `survivor_entries` owner_id and used_teams, and READS BACK the owner ID. On retry, an existing owner row is idempotent. The server then adds the link to the private local fallback as a secondary readback ONLY after authoritative DB confirmation. Parallel account-summary and Survivor initial requests share an in-process owner promise, avoiding two claims. Invalid/unavailable storage fails closed with a recoverable loading/retry message; it cannot reveal private pool details to a different email.
- The existing *optional* manual `POST /api/survivor/link-entry` route remains available for other previously unassigned participant entries, but now refuses claims of an already preassigned reserved entry from any nonmatching verified account, even if a prior code leaked. The current owner does not need a claim code.
- The prominent signed-in Survivor card no longer says `Use your exact entry name and one-time claim code`: it only shows `No entry assigned to this sign-in yet` when the authenticated email has no preassigned entry, with `Refresh my entries` action. A transient loading state prevents false unlinked flashes. The old manual claim form is hidden under a collapsed `Need to connect another entry? Optional pool-manager claim` disclosure, not shown as the primary postlogin experience. On successful autolink, the regular personal Survivor owner command desk, Week 4 scorecards, used-team history and Week 5 no-pick record load automatically and the manual form stays collapsed.
- Never changes model weights, original NFL market/source provenance, Survivor forecasts, personal picks or game results; no betting action or external pool submission.
